# FAQ: Dúvidas Frequentes da NakeDev Framework

Este documento responde às dúvidas mais comuns sobre como integrar a Framework aos seus projetos finais, respeitando o [Anti-Roadmap](FRAMEWORK_ANTI_ROADMAP.md) e o Guia de Extensibilidade.

---

### 1. Posso alterar o Sistema de Interação para usar Raycast (estilo FPS) em vez da esfera padrão?
**Sim!** O principal script de interação é o `InteractionScanner.cs` (que por padrão procura itens ou portas na frente do jogador usando um OverlapSphere). Com a nova arquitetura, os métodos dele são `protected virtual`. 
* **Como fazer?** Basta herdar este script no seu projeto e alterar a matemática para usar um *Raycast* a partir da câmera, sem tocar no código original da Framework. Além disso, as interações em si são guiadas pela interface `IInteractable`, permitindo que o seu jogo tenha desde portas com trancas numéricas até baús de puzzle complexos.

---

### 2. A Framework possui um sistema de inventário de mochila? Como implemento o meu?
De acordo com o Anti-Roadmap, a Framework **não possui um inventário de mochila**. Ela possui um `CharacterEquipmentManager`, que gerencia exclusivamente "o que está na mão do jogador neste exato momento".

**Como você deve implementar no seu jogo:**
1. Crie um sistema próprio no seu projeto (ex: `InventorySystem.cs`).
2. Esse script será responsável pela lógica do seu inventário (ex: gerenciar maleta, guardar itens de cura e munição reserva).
3. Quando o jogador "Equipar" uma arma na sua UI de inventário, o seu sistema chama a Framework: *"Ei `CharacterEquipmentManager`, equipe esta arma!"* (usando `equipmentManager.EquipWeapon(weaponStats)`).
A Framework cuidará da arma equipada sem precisar saber como o seu inventário funciona.

---

### 3. Como a Framework lida com Loadings de Cena, Saves do jogo e Cutscenes?
A Framework cuida apenas do *Momento a Momento* (Gameplay Tático). Sistemas macro como Loadings, Saves e Cutscenes devem ser centralizados no "Orquestrador" (GameManager) do seu próprio jogo.

**Como você deve implementar no seu jogo:**
1. **Saves:** Crie um `SaveManager` que lê os dados do jogador (ex: arquivo `.json`). O seu script lerá que o jogador tem 50 de vida e enviará a ordem para a Framework: `frameworkHealth.SetHealth(50)`.
2. **Cutscenes:** O seu script deve desativar o input da Framework (`playerInputReader.Disable()`), rodar a Timeline da cutscene no Unity e, ao final, devolver o controle ao jogador (`playerInputReader.Enable()`).
3. **Loadings:** A sua cena de menu principal deve ser independente. Quando o Loading terminar, simplesmente instancie (spawn) o Prefab do Jogador (que contém os scripts da Framework) no cenário.

### 4. Como aplico efeitos de status (Veneno, Fogo, Sangramento) se as armas da Framework causam apenas dano bruto?
Você utilizará **Eventos** e **Herança** para expandir a funcionalidade.

**Como fazer:**
1. **Novos tipos de tiro:** Se uma arma precisar causar dano de Fogo, você herda `CharacterRangedCombat`. No método `PerformShoot()` (que é `virtual`), você invoca a lógica base do tiro e instancia uma partícula de faísca ou projétil flamejante.
2. **Aplicando o Status:** Quando o inimigo é atingido, o evento `OnTakeDamage` é disparado. Se o inimigo for vulnerável a fogo, um script próprio seu (ex: `BurnStatusLogic.cs`) escuta esse evento e aplica o dano contínuo ao longo do tempo.
A Framework garante a aplicação do dano bruto, enquanto o seu projeto adiciona os efeitos visuais e lógicas extras de status por cima.

### 5. Devo criar um único GameManager no meu projeto para controlar tudo (Inventário, Quests, Saves)?
**Definitivamente NÃO!** Isso cria uma "God Class" (Classe Deus) — um script gigantesco e difícil de manter, onde um único erro pode quebrar o jogo inteiro.

**A Regra da Modularidade (Manager of Managers):**
O seu `GameManager` deve atuar como um Maestro: ele rege, mas não toca os instrumentos.
* Crie scripts separados para responsabilidades específicas (ex: `InventoryManager.cs`, `SaveManager.cs`, `QuestManager.cs`).
* O seu `GameManager` apenas coordena a comunicação entre eles.
* **Exemplo prático:** O jogador pausa o jogo. O `GameManager` congela o tempo (Time.timeScale = 0) e avisa o `InventoryManager`: *"Abra a interface do inventário"*. O GameManager **não sabe** desenhar o inventário na tela, ele apenas delega a tarefa. Isso mantém seu código limpo, modular e blindado contra bugs.
